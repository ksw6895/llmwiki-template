## 컨텍스트 (먼저 읽기)

- **Vault root**: `__VAULT_ROOT__/`
- 이 워크플로의 모든 vault-relative 경로(`02-Notes/`, `99-MOCs/`, `04-Areas/learning/`)는 vault root 기준입니다. 호출 시 cwd가 vault가 아니어도 vault root에 절대경로로 풀어 쓰세요.
- 작업 전에 `__VAULT_ROOT__/AGENTS.md`를 읽어 컨트랙트를 적용하세요.

사용자가 지정한 노트/토픽을 기반으로 **이해 확인 퀴즈**를 출제합니다. 답은 vault 안에 있으므로 사실 기반 검증이 가능합니다.

## 입력

`$ARGUMENTS`: 다음 중 하나
- 노트 경로 (예: `02-Notes/jwt-token-refresh.md`)
- 토픽 슬러그 (예: `security` → `99-MOCs/moc-security.md`의 노트들을 모두 대상)
- 빈 입력: 최근 7일 이내 추가된 영구 노트 중 무작위로 선택.

## 절차

1. **대상 노트 수집**: 단일 노트 또는 MOC가 가리키는 노트들.
2. **본문에서 사실 추출**:
   - 정의, 절차, 인과 관계, 숫자/날짜, 인물·결정.
   - 사용자가 적었던 **자기 생각·평가**는 별도로 표시(이건 객관 사실이 아니므로 퀴즈에 제한적으로만).
3. **퀴즈 형식** (다양하게 5문항):
   - 객관식 (4지선다) — 정의/구분
   - 빈칸 채우기 — 핵심 용어
   - 짧은 서술 — "왜 이 결정을 했는가?" 류
   - 적용 문제 — "이 상황에서 어떻게 할 것인가?" (vault의 패턴 적용)
   - 연결 문제 — "이 노트와 가장 관련 깊은 다른 노트는?"
4. **출제 + 채점 흐름**:
   - 한 번에 모든 문항을 보이지 말고, **한 문항씩** 출제하고 사용자의 답을 기다림.
   - 답이 들어오면 정답/오답 + **출처 wikilink**와 함께 해설.
   - 모든 문항 끝나면 점수 요약 + 약한 토픽 식별.
5. **학습 로그**:
   - 약한 토픽은 `04-Areas/learning/weakness-log.md`에 append (없으면 생성). 다음번 학습 우선순위에 활용.
6. **log.md append**: `## [time] quiz | <target> | score X/5`

## 출력 (예시 첫 문항)

```
📚 퀴즈: [[99-MOCs/moc-security]] (5문항)

문항 1/5 — 객관식
JWT의 refresh token이 access token과 다른 점은?
  A) 더 짧은 만료 시간을 가진다
  B) 서버에 저장되지 않는다
  C) HttpOnly 쿠키로 전달되는 것이 권장된다
  D) 사용자 ID를 직접 포함한다

답을 입력하세요 (A/B/C/D).
```

추가 입력: $ARGUMENTS (노트 경로 또는 토픽)
