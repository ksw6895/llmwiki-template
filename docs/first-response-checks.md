# 첫 설명의 회귀 사례

README를 바꿀 때 참고하는 문서 검토 사례입니다. 특정 모델의 답변을 강제하거나 이 사례만으로 실제 응답 품질을 보장하지 않습니다. 실행 절차나 필수 온보딩 체크리스트가 아닙니다.

## 실제 링크 테스트에서 나온 실패

사용자가 일반 웹 채팅에 링크와 “이게 뭐야?”를 전달했을 때, 답변은 오픈소스 템플릿·RAG·폴더 구조·내부 지침 설명 뒤에 `git clone`, `cd`, `claude` 실행을 제시했습니다. 저장소에 없는 `wiki/concepts` 같은 구조도 설명했습니다. 이는 사용자가 제공한 실패 응답의 요약입니다.

설명 요청을 기술 설정 과제로 바꾸었고, 실제 확인한 구조 대신 일반론을 섞었습니다. 기대하는 답변은 AI가 사용자의 맥락을 다음 작업에서도 이어받고, 사람도 위키를 읽고 다듬는 효용을 쉬운 예로 설명하는 것입니다. 사용을 원할 때는 파일을 다룰 수 있는 코딩 어시스턴트가 필요하다고 설명합니다. Codex나 Claude Code를 이용 중이라면 그쪽에 링크와 “내 위키로 쓸 수 있게 준비해줘”를 전달하는 것이 다음 행동입니다. 기술 준비는 코딩 어시스턴트가 맡으며 새 유료 가입을 기본으로 요구하지 않습니다.

## 상황별 점검 예시

| 입력과 환경 | 기대하는 전달·행동 | 피할 오해 |
|---|---|---|
| 링크 + “이게 뭐야?” | AI가 관심사·진행 중인 일·결정 맥락을 이어받고 사람도 읽고 다듬는 위키라는 쉬운 설명. 제공·허용한 자료를 바탕으로 함 | RAG·폴더 트리·설치 명령을 입문 답변으로 덤프 |
| “쓰고 싶어”, 실제 파일 도구 있음 | 에이전트가 준비 담당, 미정 저장 위치 등 필요한 선택만 확인 | 사용자에게 Git·터미널 절차를 숙제로 넘김 |
| “쓰고 싶어”, 파일 도구 없는 웹 채팅 | 여기서 준비할 수 없다고 알리고, 이용 중인 Codex/Claude Code 등 코딩 어시스턴트에 링크와 준비 요청을 전달하도록 안내 | 파일을 만들었다고 주장하거나 모델 이름만으로 실행 능력을 추정 |
| “처음부터 매일 저녁 정리해줘” | 첫 메모를 선행 조건으로 요구하지 않음. 소스·시간대·스케줄러와 예약 실행 환경 접근을 확인 | 모든 웹 대화를 읽거나 무조건 예약할 수 있다고 약속 |
| “폴더 구조와 Git 설정을 설명해줘” | SETUP의 실제 구성과 필요한 기술사항을 설명 | 기술 질문까지 회피하거나 존재하지 않는 `wiki/concepts` 구조를 생성 |
| “Windows에서 Obsidian까지 준비해줘” | native 파일 도구/PowerShell로 준비. 기존 앱·설정 보존, vault 등록 확인. 필요한 OS/UI 선택만 사용자에게 안내 | WSL·Git Bash·심링크 설정을 기본 숙제로 요구하거나 앱 실행만으로 등록 완료라고 주장 |
| “내 다른 웹 대화도 포함돼?” | 실제 연결하거나 제공한 범위만 포함한다고 짧게 설명 | 전체 대화가 자동 수집된다고 표현 |

상황에 맞는 답변 예:

- 설명 요청: “AI가 나의 관심사와 진행 중인 일을 다음 작업에서도 이어받도록, 나와 AI가 함께 읽고 다듬는 위키의 틀이에요. 내가 제공하거나 연결을 허용한 자료를 바탕으로 합니다. 실제로 쓰려면 파일을 다룰 코딩 어시스턴트가 필요합니다. Codex나 Claude Code를 이용 중이라면 그쪽에 이 링크와 ‘내 위키로 쓸 수 있게 준비해줘’를 전달하면 됩니다.”
- 파일 도구가 있는 사용 요청: “준비를 도와드릴게요. 어디에 둘까요? 이미 쓰는 기록장이 있으면 그 위치를 알려주세요.” 이미 위치를 알려줬다면 다시 묻지 않고 요청 범위에서 준비합니다.
- 파일 도구가 없는 사용 요청: “이 채팅에서는 파일을 만들어 준비할 수 없어요. 파일을 다룰 수 있는 코딩 어시스턴트가 필요합니다. Codex나 Claude Code를 이용 중이라면 그쪽 새 대화에 이 링크와 ‘내 위키로 쓸 수 있게 준비해줘’를 붙여 넣으세요.”
- 고급 기술 질문: “실제 폴더는 `00-Inbox/`와 `01-Daily/`, `02-Notes/` 등이며 구성 표는 SETUP에 있습니다. 로컬 Markdown 기록과 참고 워크플로를 제공하고 별도 RAG 서버는 포함하지 않습니다.” Git 준비 방법을 물었다면 SETUP의 해당 명령을 설명할 수 있습니다.

표현은 사용자의 질문에 맞게 바꿉니다. 실제 모델 테스트를 한다면 README만 읽게 한 설명 요청과 기술 문서까지 참고할 실행 요청을 구분해 결과를 살펴볼 수 있습니다. 문서의 정적 검토를 실제 Gemini 등 외부 모델 검증 결과로 보고하지 않습니다.
